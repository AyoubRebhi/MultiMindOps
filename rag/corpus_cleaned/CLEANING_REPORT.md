## Key decisions

1. **Body preserved verbatim** (whitespace-normalized only). Terminology normalization is applied to the metadata layer (`tags`, `service`) — which drives hybrid-retrieval filtering — rather than rewriting infra guidance, to guarantee technical accuracy. The corpus was already terminologically consistent.
2. **Master index excluded from embeddings.** `terraform/aws_infra_kb_index.json` is corpus metadata, not knowledge; embedding it would pollute retrieval. Its `query_examples` are preserved as `evaluation_queries.json` for recall@k testing.
3. **`.tf` files explained, not dumped.** Each Terraform file is converted to knowledge entries (what it does / when to use / best practices / security considerations) grounded strictly in the file's own comments and resources.
4. **`chunk_hint` marks category-run boundaries**: `start` opens a semantic group (safe to cut before), `continue` stays in it, `end` closes it (safe to cut after). Each entry remains a complete ~400-600 token unit — no aggressive splitting.
5. **Near-duplicates surfaced, not silently removed**, so the human/owner controls the dedup policy. Only exact within-file duplicates are auto-removed.
